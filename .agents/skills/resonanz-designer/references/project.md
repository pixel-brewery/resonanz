# Resonanz design contract

Read with [Designer](../../designer/SKILL.md), [mandatory project integration](../../designer/references/project-integration.md), root [AGENTS.md](../../../../AGENTS.md) and [the architect's frontend contract](../../resonanz-architect/references/frontend.md). Preserve the user's requested mode, existing product scope and executable owners.

## Foundations and runtime owners

- The owner-approved [theme export](../../../../resources/themes/resonanz-soho.ts) is canonical: **Soho** anatomy, warm beige surfaces, wine-red/rose primary, **Georgia** serif typography and complete **light/dark** modes. Its supporting role retains the explicitly exported Inter/system fallback. These are deliberate product values; do not reset them to the shared Soho defaults or download another font.
- [ResonanzTheme.ts](../../../../apps/renderer/src/configuration/ResonanzTheme.ts) projects that export into Mosaik's public typed `ThemeOverride`. Both [ShellConfig](../../../../apps/renderer/src/configuration/ShellConfig.ts) and [MiniRecorderConfig](../../../../apps/renderer/src/configuration/MiniRecorderConfig.ts) apply the same overrides through `provideTheme`. [AppearanceService](../../../../apps/renderer/src/services/AppearanceService.ts) follows the actual light/dark/system preference. A layout or appearance change must not remount the capture/form owners or split the two bootstraps' theme sources.
- [The authored theming guide](../../../../docs/architecture/frontend/theming.md) owns the exported body/button sizes, compact headings, custom-visualization scope, primary step-zero on-colors, Inter fallback and native icon/brand generation. Keep `--resonanz-favorite-color` confined to the owner-approved favorite accent through public foreground styling. Product visualizations retain their typed measurements and tabular alignment; this is not a general license to rebuild controls or paint unrelated app chrome.
- [tools/design-md.config.json](../../../../tools/design-md.config.json) binds base `soho`, the `resonanzTheme` export and both generated projections: [DESIGN.md](../../../../docs/architecture/frontend/generated-design/DESIGN.md) and [COMPONENTS.md](../../../../docs/architecture/frontend/generated-design/COMPONENTS.md). `yarn design:md` regenerates them; `yarn design:md-check` checks drift. Edit the maintained export/configuration and regenerate through the owner; never hand-edit generated regions.
- Preserve the documented validator compatibility limit: the historical theme validator disagrees with the exported contrast-aware step-zero colors and generated dark palettes. Keep the actual typed export and real light/dark checks; do not mutate it merely to satisfy older palette assumptions or describe that remote validation as passed.
- Interface language is **English by default**, with complete English/German catalogs under `libs/intl`. Keep user recordings, transcripts, titles, native/provider messages and saved answers in their original language. UI locale, recognition locale, voice and conversation instructions are distinct state.

## Framework, surfaces and product design

- The surface is a native Electron desktop app with standalone Angular, OnPush, Signals, supported Signal Forms and focused presenters. Read [the frontend guide](../../../../docs/architecture/frontend/README.md), [authored component catalog](../../../../docs/architecture/frontend/components.md) and [reference decisions](../../../../docs/architecture/frontend-reference.md). TypeScript, markup and SCSS retain matching owners; reusable visualizations take typed inputs and emit actions, while presenters project actual session data.
- Keep the unified native-drag toolbar, contextual screen actions and bounded content scroll bodies documented by the frontend guide. Navigation, split panes, fixed headings/actions and overlays preserve keyboard/focus paths, persisted pane sizes and valid measured widths. Real Mosaik Split, Card, feedback and form compositions keep their documented public contracts.
- Preserve existing recordings, selected session/evidence, player position, pending questions, form drafts and capture ownership across navigation, appearance and layout updates. Empty/silent waveform data and unavailable capabilities remain honest; fixtures never imply actual recording, speech or model execution.
- The passive mini recorder is a separate native window with a bounded projection of the existing capture. Its bootstrap owns no workspace, account or media initialization. Preserve its passive-frame allowlist and session-bound actions; the main renderer remains the capture owner.
- Keep Renderer → typed preload → Main → Utility. Views never gain Node, shell, arbitrary filesystem or credentials. Native menus/dialogs, permissions and system speech remain host-owned. New UI work does not authorize another microphone/recognition lease, account login, assistant CLI installation or a paid audio/cloud speech fallback. The product remains keyless through system speech and the existing Synapse integration.
- [Internationalization](../../../../docs/architecture/frontend/internationalization.md) owns stable `loc.resonanz.*` keys, whole phrases, matching `{0}` placeholders and the reactive facade/pipe. Translation, appearance and weekly/date grouping changes preserve ongoing recording and session state rather than rebuilding those owners.

## Catalog and component versions

[The MCP setup](../../../../docs/architecture/mcp.md) binds the canonical [.vscode registry](../../../../.vscode/mcp.json) and native client definitions. The only active Mosaik connection is local stdio **`mosaik`**, launched as **`yarn exec mosaik-mcp`** from the preinstalled exact `@pixel-brewery/mosaik-mcp@0.1.192` development dependency. Do not add an HTTP connection, use a second server name or download a package at runtime. Apply the shared mandatory catalog workflow through this server and report its package version and the IDs actually consulted. If a required call fails, retry once, report the exact failure and pause the dependent design decisions; do not silently fall back to the web, remembered APIs or raw local documentation. Authenticated cloud Studio operations remain outside this offline public catalog.

The shipped runtime baseline remains Mosaik **0.1.183**, established by [vendor provenance](../../../../vendor/mosaik/provenance.json), [the root manifest](../../../../package.json) and the installed public APIs. Compare the local catalog with that exact baseline before using any tag, prop, event, slot or theme field. Installing the documentation snapshot does not upgrade runtime packages or authorize modifying vendored archives and provenance.

## Verification and environment

Use the central [Designer checker](../../designer/scripts/check_design.py) on the complete changed renderer owner and its styles. Keep the product-specific `yarn ui:check`: [check-mosaik-controls.mjs](../../../../tools/check-mosaik-controls.mjs) verifies the actual toggle naming/binding/unavailability contract and supplements the shared checker. Run focused configured Nx/build/lint/type/behavior checks appropriate to the change and `yarn design:md-check` for theme projection drift; regenerate only when maintained inputs changed.

Run `yarn verify:skills` after guidance changes and `yarn verify:public-content` for public content. Inspect actual affected flows, keyboard paths, widths, reduced-motion handling and both appearances. Keep [the verification record](../../../../docs/project/verification.md) honest: a source scan/build does not prove microphone permissions, native speech, account inference, recording recovery, another OS or packaged behavior.

Follow [the architect's local execution rules](../../resonanz-architect/references/project.md#local-execution) and root `AGENTS.md`: designated checkout, ignored `.codex-work` scratch only, one global heavy job, the existing permitted native/browser sessions and explicit cleanup. No system-temp project copies, private runtime, extra microphone/provider process, release or deployment is implied by design work.
